# Editorial Patterns

Choose one pattern, then delete blocks that do not help the reader. Use the shared `.dh-seo-post` styles instead of copying article-specific CSS.

## Practical guide

1. Answer the search question in the first two or three sentences.
2. State who the guide is for.
3. Explain the process with concrete `h2` headings.
4. Add one checklist, table, example, or `.dh-note` only when it reduces ambiguity.
5. End with one `.dh-cta` containing one `.dh-cta-button`.

## Official announcement

1. State what changed, who is affected, and the effective or application date.
2. Separate confirmed notice facts from Docshunt interpretation.
3. Link the official notice in the body and `verification.sources`.
4. Use a table only for eligibility, schedule, documents, or evaluation criteria.
5. Add a final-notice reminder and one CTA.

Reference post:

- `docshunt-modoo-startup-ai-solution-provider`

## Case study or interview

1. Open with the subject, situation, and result without inflating causality.
2. Show the initial problem, actions, evidence, and lesson in that order.
3. Label hypothetical examples and unverifiable outcomes explicitly.
4. Use descriptive local images with captions when they prove the story.
5. End with the lesson for the reader and one CTA.

## Minimum quality bar

- Title, description, opening answer, headings, and CTA express the same intent.
- Claims involving dates, money, eligibility, performance, or named organizations have a source.
- `paragraphs` remains a useful plain-text fallback.
- Each inline image is local, descriptive, compressed, and has useful `alt` text.
- Exactly one primary Docshunt CTA appears.
- Avoid generic phrases such as “혁신적인 솔루션” unless evidence immediately follows.
- Prefer observed customer behavior, constraints, examples, and next actions over adjectives.
